Benign XSS proof-of-concept payloads

Small, self-identifying scripts that prove a cross-site scripting injection point executes, and do nothing else. Used by Virtue Security consultants during authorized engagements so that evidence in a report never depends on a third-party host or an attack payload.

Found this URL in your logs?

Someone loaded a script from this repository into one of your pages. That means a cross-site scripting vulnerability was reachable there: the page executed JavaScript from an origin you do not control.

If you have an active engagement with Virtue Security, this is almost certainly your tester. If you do not, treat the injection point itself as a real finding and fix it: these files are harmless, but nothing stopped a different script from loading in the same position.

Every file here is readable in full at github.com/VirtueSecurity/xss-poc. Questions: info@virtuesecurity.com.

What these payloads will never do

  • Make a network request of any kind: no fetch, XMLHttpRequest, sendBeacon, WebSocket, or image ping.
  • Read cookies, localStorage, sessionStorage, or IndexedDB.
  • Read form fields, keystrokes, or the clipboard.
  • Call eval(), Function(), or load further code.
  • Write to storage, register a service worker, or persist across a reload.

Nothing a payload observes leaves the browser tab it runs in. The worst a stolen copy of these URLs can accomplish is drawing a banner that names the firm that published it.

The payloads

  • p.js Default

    Draws a labeled banner showing the origin, path, frame context, and execution time, plus a console line.

    Use for most findings, since it screenshots cleanly and needs no dialog dismissed.

  • a.js

    Raises a single alert() naming the executing origin.

    Use when a modal is the clearest evidence, or the page's layout swallows an injected banner.

  • t.js

    Rewrites document.title only.

    Use where DOM injection is stripped, dialogs are suppressed, or a headless capture has to show the result.

  • c.js

    Writes one labeled console line and changes nothing on the page.

    Use on production, during business hours, or anywhere a visible artifact would disturb real users.

  • m.js

    Appends an unstyled <div id="virtue-xss-poc">.

    Use under a strict CSP that blocks inline styles, or when an automated check needs a stable selector.

  • x.svg

    Self-contained SVG that renders a visible notice and executes its own embedded script.

    Use for file-upload and stored-XSS tests, including hosts that block external script sources.

  • f.html

    Script-free landing page identifying itself as external content.

    Use as the target for framing, open-redirect, and window.open demonstrations.
